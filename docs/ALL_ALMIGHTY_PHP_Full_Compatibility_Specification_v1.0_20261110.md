## 1. ALL（ALMIGHTY）言語の理念と到達目標

### 1.1 ALLとは

[確認済み] ALLは、**最終的にあらゆる既存プログラミング言語との完全互換を目指す、独立した汎用プログラミング言語**である。単純なPHPラッパーや既存処理系の切り替えUIを最終形としない。

[要求] ALL独自構文のプログラムを直接処理できる基盤を保持し、そのうえで**既存言語を1言語ずつ受け入れる**。最初の重点互換対象がPHP。将来の言語追加を妨げるPHP専用の強引な設計への固定は禁止。

狙う利用者・用途：

- 初心者：日本語の自然な語順・助詞を使った、明確に定義された構文で書ける。
- 中上級者：英語記法と日英混在記法を用い、CLI・Web・業務アプリを実用的に開発できる。
- 運用者：テスト、エラー、デバッグ、依存管理、DB、HTTP、異常系、性能を検証できる。

### 1.2 日英両記述の厳密な意味

[確認済み] 日本語は `if → もし` の単純置換だけではない。「年齢が18以上なら」「『成人です』と表示する」などの語順・助詞を含む**定義済み文型**を処理する。同じALL処理系へ日本語・英語の記述を接続する。

[要求] 自由な自然言語を推測実行する仕様にはしない。曖昧な解釈をAIが勝手に補完することは禁止。文型は文法として定義し、不正入力は位置情報付きで明確に拒否する。

### 1.3 開発Phaseの扱い

[確認済み] 当初の開発方針は、(1) ALL独自言語の実用性・完成度向上 → (2) 既存言語の完全互換を1言語ずつ → (3) 包括的セキュリティ強化・最終監査。

[確認済み] その後、所有者から**PHP互換開発を具体的に進める指示**があり、少なくとも「変数・演算子・配列」「関数・スコープ」「オブジェクト指向」の3領域は100%達成指示が出ている。

[要求] この明示指示に基づくPHP作業は続行するが、**ALL全体のPhase 1完了・Phase 2全体の完了・正式出荷を勝手に宣言しない**。ALL独自言語の機能を削除してPHP互換へ置換してはならない。

## 4. PHP「完全互換」の定義とバージョン基準

### 4.1 対象バージョン

[確認済み] 本書作成日（2026-11-10）のPHP公式サイトでは、PHP **8.5.12**が公開済みの安定系列であり、PHP 8.6.0は**RC5**（GA予定：2026-11-19）。過去のALL互換テストではPHP **8.4.24** を参照実行器として使用していた。

[提案・要決裁] **PHP 8.5.12（64bit）を当面の完全互換ターゲット基準候補**とする。既存PHP 8.4参照データは回帰資産として残す。PHP 8.6 RCを安定ターゲットへ自動で追加しない。**対象の確定は所有者決裁事項**であり、無回答で互換宣言の基準をすり替えない。

[要求] 仕様を固定する際、少なくとも次を `COMPAT_TARGET.md` に記録する。

- PHP本体の厳密なリリース番号、実行バイナリのSHA-256、ビルド情報、64bit/32bit、OS
- `php -v`、`php -i`、`php -m`、`php --ini`、拡張モジュールの有無
- 動作対象SAPI（CLI／CGI／FPM／Web実行。詳細は所有者承認で確定）
- 対象拡張の一覧（組込・標準同梱・任意追加）および環境依存差の定義
- 完全互換判定が及ぶ範囲と判定しない範囲（未決裁が残る限り「100%」禁止）

### 4.2 互換性の層（全面達成に必要な別々のゲート）

| ゲート | 定義 |
|---|---|
| G1 言語構文 | PHPの有効なソースを受け付け、無効なソースを公式PHP相当に拒否 |
| G2 意味論 | 値・参照・スコープ・評価順・制御フロー・型変換・例外・副作用が一致 |
| G3 標準機能 | 対象PHPの標準関数・クラス・定数・ストリーム・拡張APIが一致 |
| G4 実行環境 | CLI引数・入出力・終了コード・SAPIのリクエスト処理・設定・セッション等が一致 |
| G5 既存アプリ | 対象とした実PHPアプリ・Composerパッケージが無改変で動作 |
| G6 品質 | 回帰・差分・異常・境界・メモリ・性能・OS間動作を証跡で実証 |

**「PHP完全互換100%」と呼べるのは、合意済みターゲットに対するG1〜G6の全必須要件が達成され、未実装・未検証・未説明差分が0となった場合に限る。** 標準拡張・SAPIを後回しにして「言語仕様のみ100%」と呼ぶなら、その限定名を使い「PHP全体100%」と混同しない。

サードパーティの**任意のPHPネイティブ拡張のバイナリABI互換**や、あらゆる将来のPHPバージョンへの追従を保証するかは独立した決裁事項。未決裁のまま対象外にして「無条件の完全互換」を名乗ってはならない。

### 4.3 実装方式の禁止事項

[要求] PHPソースを `php.exe`、`php`コマンド、PHP-FPM、`eval`等へ丸投げし、その成功をALL独自PHP処理系の実装成功として扱うことを禁止する。**公式PHPの実行はオラクル（照合側）として許可**。PHP標準ライブラリや拡張との橋渡しが実装上必要な場合は、ラッパー化の境界・独立性への影響を明示し、事前承認を得る。

4. **trait**：メソッド／プロパティ／定数、複数合成、入れ子利用、`as`／`insteadof`、競合時の失敗、可視性・型・参照返却情報の維持。
5. **enum**：UnitEnum・BackedEnum、case同一性、`cases`／`from`／`tryFrom`、メソッド・interface・traitの制約、値不正時の例外。
6. **型付きプロパティ**：初期化前、弱い／厳密な変換、プロパティ昇格、readonlyプロパティ・readonly class、参照経由の書込み制約。
7. **PHP 8.4以降のプロパティ機能**：`get`／`set`フック、backed／virtual、非対称可視性、継承／interfaceプロパティ契約、`isset`／`empty`／`unset`、ref・readonly等との相互作用。
8. **マジックメソッド**：`__construct`、`__destruct`、`__get`、`__set`、`__isset`、`__unset`、`__call`、`__callStatic`、`__invoke`、`__toString`、`__clone`、`__serialize`、`__unserialize`、`__sleep`、`__wakeup`、`__debugInfo`、`__set_state` など、対象版に存在するすべて。
9. **Attributes**：構文、ターゲット、重複可能性、クラス・メソッド・プロパティ・引数への付与、リフレクションとの連携。
10. **オブジェクトモデル**：循環参照、破棄・GC、シリアライズ、エラー発生箇所、オブジェクト比較、動的プロパティ／廃止警告、リフレクション。
11. **関連機能との組合せ**：名前空間、autoload、例外クラス、ジェネレータ、strict_types、標準ライブラリのオブジェクト型と相互作用するケース。

**完了証明**：各クラス・メソッド・プロパティを単独で通すだけでは不十分。継承・trait・型・参照・フック・マジックメソッドを重ねたケースを公式PHPと照合し、クラス宣言時の拒否も一致させる。

## 11. 検証の厳格な受入基準

### 11.1 差分オラクル

比較対象は、単なる標準出力の文字列だけではない。

- **正常動作**：stdout/stderrのバイト列、終了コード、戻り値の型と値、配列キー順・同一性、ファイル／DB／HTTP等の副作用。
- **例外・警告**：エラー分類、発生時点、ユーザーコードから見えるクラス・コード・メッセージ、条件付き警告、例外伝播。
- **非決定性**：日時・乱数・PID・環境依存データはテスト前に条件を固定し、恣意的な期待値変更をしない。
- **数値**：桁境界、精度、指数、INF/NAN、演算順、変換規則。`decimal`で近似した結果を全面一致とはしない。
- **オブジェクト**：参照・共有・clone・destruct・GC・マジックメソッドの呼出し順。
- **OS**：対象版のOSで同一条件とし、差を説明して記録。

### 11.2 公式テスト・実アプリ

- PHP公式のPHPT（対象版に紐づく）を一覧化し、対象範囲での採用・非採用理由を記録。
- PHPTの実行を単にPHP本体に委譲しない。ALL互換処理系を被験実装として走らせる。
- Composer依存を持つ実アプリを選定し、**PHPコード変更なし**でCLIとWeb実行の一致を検証する。
- 実アプリは起動だけでなく、代表的な機能・異常系・永続化・負荷試験を含める。

### 11.3 テスト基準の保護

- 旧 **523件統合回帰**、追加デバッグ4件、直近 **716件PHP回帰** の独立性を維持。
- 既存テストの削除・件数水増し・期待値変更・`skip`化・エラーなら何でもPASS・実PHP結果の捏造は禁止。
- バグ修正のためテストの見直しが不可避なら、旧定義を別アーカイブに残し、新旧の対応表とPHPのオラクル結果を残す。
- PASS数の表示だけで卒業判定を行わない。被験コード・オラクル・判定器の役割を分離する。

### 11.4 非破壊・再現可能な検証器

[要求] PowerShell検証入口は、**前処理 → 構文検査 → 整合性検査 → 直接実行回帰 → 差分試験 → （承認後に）導入試験**の順。前段が失敗したとき後段へ進まない。

過去の失敗を再発させないための必須対策：

1. ZIP名・展開先パスを決めつけない。まず実在とハッシュを確認する。
2. `$validate`など過去のセッション変数を誤用しない。実行時に局所スコープで初期化する。
3. `.ps1`の先頭のBOMは**0個か1個**。二重BOM禁止。`[CmdletBinding()]`／`param`より前の有効な実行文禁止。
4. ハッシュテーブルの閉じ忘れ・括弧不整合をPowerShell標準パーサで検出する。独自の簡易括弧チェックだけでPASSにしない。
5. Windows PowerShell 5.1の文字コード、`$args`自動変数、`${name}`／`$name:`補間、JSON配列の1要素化、整数／decimal変換に注意する。
6. パッチを適用する場合は旧ハッシュ確認→変更→新ハッシュ確認→マニフェスト再生成→テスト。途中失敗なら旧状態を保持。
7. ZIPリンクが取得できない場合、旧版ソースへの検証可能な差分パッチ等へ切替える。存在しないZIPをダウンロード済みとして扱わない。

検証スクリプトの最低限のPowerShell入口例（**作業環境に応じて正しいファイル名を確認したうえで用いる**）：

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $package = 'C:\actual\path\to\verified_package.zip'
    if (-not (Test-Path -LiteralPath $package -PathType Leaf)) { throw 'Package not found' }
    $dest = Join-Path $env:TEMP ('ALL_check_' + [guid]::NewGuid().ToString('N'))
    Expand-Archive -LiteralPath $package -DestinationPath $dest -ErrorAction Stop
    $candidate = @(Get-ChildItem -LiteralPath $dest -Filter 'ALL_PHP_v3_12_1_validate.ps1' -File -Recurse)
    if ($candidate.Count -ne 1) { throw "Validator count is $($candidate.Count), expected 1" }
    & $candidate[0].FullName -CompileCSharp
    if (-not $?) { throw 'Validation failed' }
}
```

これは**既存アダプタの候補版を破壊せず試すための例**であり、次に作るバージョンのファイル名や合格結果を保証するものではない。Claude Codeは実ファイル名を確認して生成すること。
