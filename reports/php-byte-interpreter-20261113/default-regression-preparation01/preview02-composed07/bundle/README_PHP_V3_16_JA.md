# ALL PHP v3.16 — 名前空間

対象：PHP 8.5.12（64bit、Windows）。

## 実装した挙動

- `namespace A\B;`、`namespace A\B { … }`、`namespace { … }`（グローバル）。
- 完全修飾名（`\Foo\Bar`、`\strlen()`、`\PHP_EOL`）、修飾名（`Foo\Bar`）、相対名（`namespace\Foo`）。
- `use A\B;`、`use A\B as C;`、`use function A\f;`、`use const A\C;`、グループ形式 `use A\{B, C as D, function f, const C};`。
- 名前空間内で宣言したクラス・インターフェース・trait・enum・関数・定数は、完全修飾名で登録される。
  `get_class()`、`var_dump`、`print_r`、`::class`、例外の表示には、PHP と同じく先頭の `\` なしの完全修飾名が出る。
- 名前空間内の非修飾の関数・定数は、その名前空間に宣言があればそれを、なければグローバルのものを使う（PHP のフォールバック規則）。
- `__NAMESPACE__`、`Foo::class`。
- 型宣言（引数・戻り値・プロパティ・`catch`）、`extends`／`implements`、trait の `use`、`instanceof`、`new` の中のクラス名解決。
- 文字列で渡すクラス名・関数名（`'NS\func'`、`'NS\Class::method'`、`['NS\Class', 'method']`）。

## 実装方式

名前の解決は、構文解析の前にトークン列に対して 1 回だけ行う。`namespace` 文と `use` 文をここで消費し、
クラス・関数・定数の名前を完全修飾名に書き換える。名前空間・`use`・`\` を含まないプログラムはこの処理を通らず、
従来とまったく同じトークン列で解析される。

## 未対応として残したもの（完全互換ではない）

- 関数・定数のフォールバックは、同じソース内の宣言を解析前に調べて決めている。実行時に動的に定義されるもの
  （条件付きの関数定義、`define('NS\X', …)` で後から作る定数、別ファイルの読み込み）は、非修飾名からは見つからない。
- 名前の役割（クラス・関数・定数・型）はトークンの並びから判定している。`定数 & $変数` のように型宣言と同じ並びになる式を
  名前空間内で書いた場合、定数がクラス名として解決されることがある。
- 属性（`#[…]`）は引き続き行コメントとして読み飛ばすため、その中の名前は解決されない。
- `use` したが存在しないクラス、名前の衝突（同じ別名の二重 `use`、宣言との衝突）の検出は行っていない。
- 1 つのファイルで括弧なしと括弧ありの `namespace` を混在させた場合のエラー検出、`namespace` 文より前のコードの禁止は未実装。
- `__CLASS__`、`__FUNCTION__`、`__METHOD__`、`__LINE__`、`__FILE__`、`__DIR__` は未実装。
- `include`／`require` が未実装のため、複数ファイルにまたがる名前空間は扱えない。
