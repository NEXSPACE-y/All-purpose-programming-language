# Isolated gettext candidate: build and static preparation

This candidate has not loaded or executed `php_gettext.dll`. Its build success and import-name closure must not be counted as PHP compatibility passes. Actual native/reference comparisons wait for the root agent's serialized execution window.

The new callback core is `tools/candidates/php-native-gettext/out/callback02/php8ts.dll`, SHA-256 `75054109850920670f6bd962100b3eccef4ed8dd292ad3b8f471b23c7f9ecd9a`. It is a new build from `generated03`, based on the unchanged info-v2 callback source `c0c35e44e8d8213142b27bb963756bae2970747b05cec5e0ecd3483e62469c05`. The original info-v2 core `204f885944390be8e0b1e84a4ae3aafc5d85fd674fc35e9077b63fa5baa77f26`, its legacy counterpart and all existing fixtures remain unchanged. Full source differences and original/candidate hashes are in `generated03/provenance.json` and adjacent patches.

Four missing SDK exports now have own implementations. Value errors use the active native function and argument metadata, preserve existing errors, format bytes and remain readable through the sized error getter. The empty-argument export calls that same producer. The virtual-directory APIs retain independent state in the existing thread-local request object. Request start snapshots host cwd; an explicit sized-byte setter synchronizes subsequent host virtual-directory changes. Resolution constructs absolute paths from that state, checks the actual filesystem through a Windows file handle, resolves its final name and converts through strict UTF-8. Request end clears this state. Neither resolution nor the setter calls process `chdir`/`SetCurrentDirectory`.

The current profile states its UTF-8 Windows path contract explicitly. General PHP code-page switching, POSIX paths, filesystem-cache policy, all device/UNC/drive-relative corner cases and SAPI integration remain unverified. The Win32 handle/canonicalization rules require actual comparison; implementation is not evidence that they match every PHP realpath detail.

The SDK inlines `Z_PARAM_PATH_STR` validation and reports its NUL rejection through the pre-existing `zend_wrong_parameter_type_error` export. This candidate therefore also handles its PATH/PATH_OR_NULL string failure as a ValueError and supplies the corresponding string/nullable string type names. The fixed PHP source archive's `Zend/zend_API.c:303-306` and SDK inline path parser are the contract evidence. This change is isolated to the new candidate and is not a rewrite of the frozen regression expectations.
